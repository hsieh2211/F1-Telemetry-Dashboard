# F1 遙測儀表板

網站只讀取已保存的 JSON，不會在訪客切换選單時連線抓取 F1 資料。
收錄範圍是各分站正賽（R）及排位賽（Q）的「每位可用車手最快圈」，不是全場逐圈資料。
練習賽、衝刺賽及衝刺排位賽不在本次範圍內。

## 使用方式

1. 選擇分站與正賽／排位賽。
2. 已有有效資料：顯示車手選單及比較圖。
3. 尚未到預定時間：顯示「尚未開賽」。
4. 已到時間但沒有檔案：顯示「資料尚未收錄」或「比賽進行中或資料整理中」。
5. 檔案损壞或車手不足：顯示提示；其他分站及教學百科仍可使用。

下拉選單的「已存 n/2 場」是檔案數；選取後仍會檢查內容是否有效。
賽程來自 FastF1，保存在 `data/schedule_2026.json`；可能改期，請定期更新。
時間已換算為 UTC；不以瀏覽器當地時區判斷。

## 之後新增已完賽資料（在自己的電腦執行）

先下載合併後的 GitHub 專案，解壓縮，以 VS Code 開啟資料夾。
若舊專案中已有 `f1_cache_v99`，可把該快取資料夾複製到新專案，以減少重複下載。
在該資料夾的終端機執行：

```powershell
py -m pip install -r requirements.txt
py export_data.py --year 2026
```

每次執行會先更新賽程；依序處理已過預定開賽時間至少六小時的 R／Q 場次。
六小時只是下載等待期，不當作完賽證明；另檢查 FastF1 的 `Finalised` 狀態。
缺少結束狀態、圈速或有效遙測時，不匯出假資料。
已存在且通過驗證的檔案會略過；中斷後重新執行同一指令即可接續。
連續三場失敗則停止後續下載，避免反覆請求。遇到存取限制請停止並檢查授權或服務狀態，不使用代理繞過。

完成後將 **data 整個資料夾** 上傳到 GitHub 專案根目錄，並提交變更。
確認 GitHub 的路徑是 `data/schedule_2026.json` 及 `data/2026_..._r.json` 等，
不要把新資料檔全部放在根目錄，也不要上傳 `f1_cache_v99`。
提交後等待 Streamlit 重新部署，再確認新增的場次。
未來新比賽結束後仍須重新執行並上傳；網站沒有自動排程下載。

逐場結果保存在 `data/export_report_2026.json`：
- `exported`：此次成功匯出。
- `saved`：已有有效檔案。
- `future`：尚未開賽。
- `waiting`：等待比賽結束及資料整理。
- `unknown`：開賽時間尚未確認。
- `failed`／`not_attempted`：下載失敗或尚未處理，不能宣稱已有資料。

只更新指定分站：
```powershell
py export_data.py --year 2026 --event "Australian Grand Prix"
```

若要重新抓取已保存場次，加入 `--refresh`；下載失敗會保留原有效檔案。
`--saved-schedule` 使用本機賽程快照，不刷新賽程（需自行確認沒有改期）。
本版本網頁讀取 2026 賽程；其他年份匯出不會自動加入網頁選单。

## 資料品質及測試

資料會檢查年份／場次、數值、時間與距離遞增、圈速與遙測對應、至少兩位有效車手。
沒有有效最快圈的車手不列入比較；匯出檔 `skipped_drivers` 記錄原因。
最快圈時間差是依行駛進度對齊的近似值，不是官方即時差距。
原根目錄 `2026_australia_race.json` 保留相容，不需刪除。

```powershell
py -m unittest test_race_data test_app -v
py -m streamlit run demo.py
```

專題進度可簡述：「將資料下載與網頁展示分開，預先保存各分站最快圈資料，並加入未開賽、資料缺漏及讀檔錯誤提示，避免切換場次時中斷。」
