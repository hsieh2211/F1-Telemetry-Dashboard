# F1 遙測儀表板

網站只讀取已保存的 JSON，不會在訪客切换選單時連線抓取 F1 資料。
最快圈資料支援正賽（R）、排位賽（Q）與有收錄的衝刺賽（S）。
整場節奏另讀取 `.laps.json` 逐圈檔案；既有最快圈檔案無法還原整場資料。
練習賽與衝刺排位賽不在目前範圍內。

## 使用方式

1. 選擇分站與正賽／排位賽。
2. 已有有效資料：顯示車手選單及比較圖。
3. 尚未到預定時間：顯示「尚未開賽」。
4. 已到時間但沒有檔案：顯示「資料尚未收錄」或「比賽進行中或資料整理中」。
5. 檔案损壞或車手不足：顯示提示；其他分站及教學百科仍可使用。

下拉選單的「已存 n/m 場」是最快圈檔案數，不代表已有逐圈檔案；選取後仍會檢查內容是否有效。
賽程來自 FastF1，保存在 `data/schedule_2026.json`；可能改期，請定期更新。
時間已換算為 UTC；不以瀏覽器當地時區判斷。

## 之後新增已完賽資料（在自己的電腦執行）

先下載合併後的 GitHub 專案，解壓縮，以 VS Code 開啟資料夾。
若舊專案中已有 `f1_cache_v99`，可把該快取資料夾複製到新專案，以減少重複下載。
在該資料夾的終端機執行：

```powershell
py -m pip install -r requirements.txt
py export_data.py --year 2026
```

每次執行會先更新賽程；依序處理已過預定開賽時間至少六小時的 R／Q 場次。
六小時只是下載等待期，不當作完賽證明；另檢查 FastF1 的 `Finalised` 狀態。
缺少結束狀態、圈速或有效遙測時，不匯出假資料。
已存在且通過驗證的檔案會略過；中斷後重新執行同一指令即可接續。
連續三場失敗則停止後續下載，避免反覆請求。遇到存取限制請停止並檢查授權或服務狀態，不使用代理繞過。

完成後將 **data 整個資料夾** 上傳到 GitHub 專案根目錄，並提交變更。
確認 GitHub 的路徑是 `data/schedule_2026.json` 及 `data/2026_..._r.json` 等，
不要把新資料檔全部放在根目錄，也不要上傳 `f1_cache_v99`。
提交後等待 Streamlit 重新部署，再確認新增的場次。
未來新比賽結束後仍須重新執行並上傳；網站沒有自動排程下載。

逐場結果保存在 `data/export_report_2026.json`：
- `exported`：此次成功匯出。
- `saved`：已有有效檔案。
- `future`：尚未開賽。
- `waiting`：等待比賽結束及資料整理。
- `unknown`：開賽時間尚未確認。
- `failed`／`not_attempted`：下載失敗或尚未處理，不能宣稱已有資料。

只更新指定分站：
```powershell
py export_data.py --year 2026 --event "Australian Grand Prix"
```

若要重新抓取已保存場次，加入 `--refresh`；下載失敗會保留原有效檔案。
`--saved-schedule` 使用本機賽程快照，不刷新賽程（需自行確認沒有改期）。
本版本網頁讀取 2026 賽程；其他年份匯出不會自動加入網頁選单。

## 資料品質及測試

資料會檢查年份／場次、數值、時間與距離遞增、圈速與遙測對應、至少兩位有效車手。
沒有有效最快圈的車手保留在名單並顯示原因，不能繪製其最快圈比較；匯出檔 `skipped_drivers` 記錄原因。
最快圈時間差是依行駛進度對齊的近似值，不是官方即時差距。
原根目錄 `2026_australia_race.json` 保留相容，不需刪除。

```powershell
py -m unittest test_race_data test_app -v
py -m streamlit run demo.py
```

專題進度可簡述：「將資料下載與網頁展示分開，預先保存各分站最快圈資料，並加入未開賽、資料缺漏及讀檔錯誤提示，避免切換場次時中斷。」
# 2026 首頁與離線分析入口

執行 `streamlit run demo.py` 會先進入 2026 首頁，預設展示美國站。
選擇分站與場次後，「直接分析」會把選擇帶進原有儀表板；「帶我看懂」提供相同場次的真實最快圈圖表、比較條件與方法說明。

首頁只讀取 `data/schedule_2026.json` 及對應離線檔案，來源與匯出時間來自檔案內的 metadata。匯出時間轉為台灣時間，不當作網站上線時間。圖表不是整場節奏或官方分段計時；車手與車隊名單僅代表所選場次。2026 技術規則專頁尚未完成核對，首頁不提供推測內容。資料檔本身沒有在此改動。

驗證：`python -m unittest test_homepage test_app test_race_data -q`。
此版本先供程式審查，發布前仍需以桌面與手機瀏覽器確認排版及操作。

## 第二階段：逐圈節奏、輪胎使用與進出站紀錄

在已安裝套件的專案資料夾執行（學校 Windows 虛擬環境）：

```cmd
.venv\Scripts\python.exe export_data.py --year 2026 --event "Las Vegas Grand Prix" --sessions R --saved-schedule --race-laps
```

成功會產生 `data/2026_las_vegas_grand_prix_r.laps.json`，不改寫原來的 `_r.json` 與 `_q.json`。
上傳這個新檔案後，分析頁的「整場節奏與輪胎」即可使用。未收錄時只顯示提示，不以最快圈補造逐圈資料。
家裡的環境可將 `.venv\Scripts\python.exe` 換成原本的 Python 完整路徑。
使用 `--race-laps` 時預設 R，亦支援 `--sessions R S`；不支援 Q。報告另存 `export_laps_report_2026.json`。
重跑會略過通過驗證的檔案；加 `--refresh` 可更新，失敗保留原檔。

逐圈檔案版本 `schema_version=1`、`kind=race_laps`。保留完整匯出車手名單與全部可定位圈次，包含缺少圈速或品質旗標的紀錄；缺少車手／圈次的資料只計入 `omitted_rows`，不能定位到圖上。時間欄位以秒儲存；場次時間原點沿用 FastF1，並非台灣時間或換胎停車時間。

- 節奏：沿用側欄 A／B 車手，可額外加入兩位車手；可選圈次範圍，顯示有效圈中位數與互動逐圈曲線。未採用的圈另列標記，可查看排除原因；資料缺口保留斷點。
- 篩選：排除起跑圈、進出站圈、非全圈綠旗、計時不可靠、刪圈、補建圈及相關旗標缺漏。沒有快速圈百分比門檻，沒有隱藏移除慢圈。
- 輪胎：互動逐圈胎種圖與依 stint／胎種整理的紀錄、有效圈數及中位數。缺漏不補值。
- 進出站：顯示來源時間與圈次；不推論停車秒數、維修區損失或 undercut 成敗。
- 原始表：可檢查每圈排除原因，下載所選紀錄 CSV。

有效圈中位數未校正油量、交通、天候與輪胎條件；目前不宣稱純輪胎衰退率、策略優劣或因果分析。真實新檔案必須經資料驗證與網站檢查後，才能宣稱該分站的第二階段分析已可用。合成資料只用於測試，不會提交到 `data/`。

驗證：`python -m unittest discover -q`。

分析頁共用分站、場次與 A／B 選擇；最快圈摘要放在「最快圈比對」分頁。圖表與摘要採統一深色配色，明細收在可展開區塊；整場圖表隨畫面寬度調整，繁中工具提示保留原始數值。
